Backend Docs for Frontend



# Railway Maintenance Optimization System

## Frontend API Integration Documentation

**Project:** AI-Powered Automatic Block Planning to Maximize Asset Availability for Train Operations

**Backend:** Node.js + Express + PostgreSQL + Prisma

**Document:** Frontend API Contract

**Status:** MVP

---

# 1. Base URL

For local development:

```text
http://localhost:5000
```

All API endpoints use:

```text
/api
```

Example:

```text
GET http://localhost:5000/api/assets
```

The frontend should store the base URL in an environment variable.

Example:

```env
VITE_API_BASE_URL=http://localhost:5000/api
```

Do not hardcode the backend URL throughout the React application.

---

# 2. General Response Format

Successful responses generally follow:

```json
{
  "success": true,
  "message": "Operation completed successfully",
  "data": {}
}
```

Error responses generally follow:

```json
{
  "success": false,
  "message": "Error description"
}
```

The frontend should always check:

```javascript
response.data.success
```

before assuming the operation succeeded.

# 17. Generate Optimized Plan

## POST `/api/planning/generate`

This is the **most important backend endpoint**.

The frontend uses this endpoint when the user clicks:

```text
Generate Plan
```

### Request

```json
{
  "start_date": "2026-09-07",
  "end_date": "2026-09-13",
  "departments": [
    "ENG",
    "TRD",
    "SNT"
  ]
}
```

### Processing

Backend performs:

```text
Maintenance Tasks
       ↓
AI Priority Engine
       ↓
Priority Scores
       ↓
Available Block Windows
       ↓
Train Schedule Constraints
       ↓
Optimization Engine
       ↓
Optimized Block Plan
       ↓
Database
```

### Response

Conceptual response:

```json
{
  "success": true,
  "message": "Block plan generated successfully",
  "data": {
    "dateRange": {
      "startDate": "2026-09-07T00:00:00.000Z",
      "endDate": "2026-09-13T00:00:00.000Z"
    },
    "departments": [
      "ENG",
      "TRD",
      "SNT"
    ],
    "tasksConsidered": 11,
    "assetsConsidered": 9,
    "trainSchedulesConsidered": 4,
    "blockWindowsConsidered": 4,
    "tasksScheduled": 2,
    "plansCreated": 1,
    "plans": []
  }
}
```

### Frontend behavior

When the user clicks **Generate Plan**:

1. Disable the button.
2. Show loading state.
3. Send request.
4. Wait for response.
5. Display success/error notification.
6. Refresh planning data.
7. Refresh dashboard analytics.
8. Display generated plan.

Example UI:

```text
Generating optimized plan...

[████████████████░░░░]

AI priority → Optimization → Saving plan
```

Do not allow multiple accidental submissions while generation is running.

# 28. Error Handling

Frontend should handle at least:

### 400

Bad request / validation error.

Display:

```text
Please check the planning parameters.
```

### 404

Resource not found.

Display:

```text
Requested resource was not found.
```

### 500

Backend/internal error.

Display:

```text
Something went wrong. Please try again.
```

### AI/Optimizer unavailable

Display:

```text
Planning service is temporarily unavailable.
Please try again later.
```

Do not expose stack traces or internal database errors to users.

# 29. API Client Structure

Recommended React structure:

```text
frontend/
└── src/
    ├── api/
    │   ├── client.js
    │   ├── assets.js
    │   ├── maintenance.js
    │   ├── trains.js
    │   ├── blocks.js
    │   ├── planning.js
    │   └── analytics.js
    │
    ├── components/
    ├── pages/
    ├── hooks/
    └── utils/
```

Example:

```javascript
// api/client.js

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL;

export async function apiRequest(endpoint, options = {}) {
  const response = await fetch(
    `${API_BASE_URL}${endpoint}`,
    {
      headers: {
        "Content-Type": "application/json",
        ...(options.headers || {})
      },
      ...options
    }
  );

  const data = await response.json();

  if (!response.ok) {
    throw new Error(data.message || "API request failed");
  }

  return data;
}
```

Then:

```javascript
// api/planning.js

import { apiRequest } from "./client";

export function generatePlan(payload) {
  return apiRequest("/planning/generate", {
    method: "POST",
    body: JSON.stringify(payload)
  });
}

export function getPlans() {
  return apiRequest("/planning");
}

export function getPlan(id) {
  return apiRequest(`/planning/${id}`);
}
```

# 32. Important Frontend Rules

### Do not hardcode backend data

Bad:

```javascript
const criticalTasks = 3;
```

Good:

```javascript
const criticalTasks = dashboardData.criticalTasks;
```

### Do not calculate backend-owned metrics unnecessarily

For example, utilization is already returned by the backend as a percentage.

Use:

```javascript
`${utilization}%`
```

instead of converting it again.

### Do not assume IDs are numeric

IDs may be strings/CUIDs.

Use:

```javascript
String(id)
```

when necessary.

### Do not assume a plan always exists

Handle:

```text
plans = []
```

gracefully.

### Always handle loading and error states.

# 36. Important Prototype Note

This system is a **prototype** using synthetic/mock data.

The frontend must not claim that it is directly controlling live Indian Railway infrastructure.

The system should be presented as:

> An AI-assisted decision-support platform for coordinated railway maintenance block planning.

Final operational decisions remain with authorized railway personnel.
